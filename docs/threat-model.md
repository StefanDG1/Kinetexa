# Threat model

Reviewed against the hosted prerelease on 6 September 2026. Production registration remains closed. This document records implemented controls and gaps; it does not certify a completed security gate.

## Assets and trust boundaries

Private assets include account identities, session tokens, activity originals, canonical streams, precise routes, health measurements, notes, conversations, billing references, provider credentials and backups. The browser, uploaded bytes, model output, webhook requests and share visitors are untrusted.

WorkOS authenticates the user. Convex validates the signed identity and resolves ownership server-side. Next.js provides authenticated navigation but is not the authorization boundary for direct backend calls. R2 stores private objects under athlete prefixes. The AI Gateway receives only consented, policy-permitted context. Stripe and Resend are separate external processors. Operator deployment credentials bypass athlete restrictions and therefore belong only in private configuration and protected CI secrets.

Public shares are intentional bearer capabilities. Authorized object downloads are short-lived bearer capabilities. Anyone holding either URL can use it until its server-enforced expiry or revocation boundary; URLs must not enter public logs or analytics. Third-party map services receive network requests from the browser and remain a privacy-policy consideration.

## Threats, controls and evidence

| Threat                             | Implemented control and evidence                                                                                                                                                                                                                                   | Remaining limit or follow-up                                                                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account takeover                   | AuthKit signed sessions; server identity checks; revoked-session hashes; logout and registration regression tests; hosted session/refresh denial and real-browser logout.                                                                                          | External WorkOS revocations and backend-outage logout can rely on JWT expiry. Auth abuse controls and recovery/MFA acceptance remain open.                                       |
| IDOR and cross-user access         | Every private product operation resolves the active athlete. Owned IDs are checked, including analytics tool arguments. Two-user authorization, sharing, export and destructive-operation tests exercise this boundary.                                            | Review every added endpoint and retain negative ownership checks when changing APIs.                                                                                             |
| Provider-token theft               | Direct connectors are disabled. WorkOS/service secrets stay in private server configuration; AuthKit handles the sealed session cookie. Raw session identifiers are not stored in revocation records.                                                              | Approved connector implementation still needs encrypted token storage, rotation, minimum scopes and revocation verification.                                                     |
| Webhook forgery/replay             | Stripe and Svix signature/timestamp verification precede writes. Logical events are idempotent. Bodies are bounded to 1 MiB before verification. Forged, repeated and valid signed events have focused and hosted checks.                                          | Persistent activity-provider webhooks are not implemented. Missing-delivery detection remains open.                                                                              |
| File-parser attack                 | FIT checksums, canonical schema validation, SAX depth/DTD/entity/UTF-8 rejection, activity size/duration/sample limits and malformed-input regression tests. Retained bytes are sealed by checksum before parsing.                                                 | Broader device goldens and fuzz/load coverage remain open. The hosted large-file result covers one synthetic GPX, not every format.                                              |
| Decompression bomb/corrupt archive | ZIP declared limits plus bounded actual writes, CRC/header/overlap checks and duplicate/unsafe-path rejection. Gzip uses bounded zlib CRC/length validation. Tests cover forged sizes and nested/traversal/bomb cases; hosted corrupt ZIP publishes no activities. | Maximum-sized ZIP/FIT/TCX memory and concurrent worker limits still need hosted measurements. Unsupported ZIP entries are not decompressed or checksummed.                       |
| XSS                                | React text rendering, closed JSON schemas, nonce script CSP through AuthKit, framing/MIME protections and hosted inline-handler blocking.                                                                                                                          | Nonce CSP and hosted map/inline-handler checks passed. Inline styles remain allowed for map/chart positioning; future rich text and full private browser acceptance need review. |
| CSRF                               | Direct Convex writes require a bearer token. AuthKit callback checks the flow's state and one-use PKCE cookie; provider exchange stays server-side.                                                                                                                | Browser destructive/auth flow review is incomplete. Same-site cookie policy alone must not be treated as full protection for future cookie-authenticated endpoints.              |
| SSRF                               | Users cannot supply backend fetch destinations. Service endpoints are configured server-side; object keys come from owned records. AI tools have no arbitrary URL/network tool.                                                                                    | Reassess before adding provider download callbacks or any user-supplied URL importer.                                                                                            |
| Prompt injection                   | The planner selects from thirteen closed deterministic tools. Schemas reject unknown actions; signed athlete context and consent leases authorize reads; output cannot execute writes or arbitrary code. Adversarial plan and consent tests exist.                 | Broader multilingual/provider-content adversarial evaluation remains open. Keyword guards alone are not the security boundary.                                                   |
| AI data exfiltration               | Source permission and consent are checked before external calls. Default context excludes exact GPS and unrestricted health history; database IDs remain server-side. Revoked consent invalidates pending work.                                                    | External model terms/retention and any future provider permissions must be rechecked before enabling new sources.                                                                |
| Public-share leakage               | Explicit selected-field projection; ownership validation; noindex; exact expiry; revocation; per-link read limits. Hosted projection parity, limit and revocation checks passed.                                                                                   | A recipient can retain already-viewed data. Invalid-token infrastructure abuse and worst-case projection CPU remain open.                                                        |
| Privacy-zone bypass                | Routes are masked on the server at every public read using current zones. Tests cover changes after link creation and cross-user zone isolation. Private response objects are never reused publicly.                                                               | Frontend map/heatmap/export acceptance must preserve their distinct private/public semantics.                                                                                    |
| Log leakage                        | Structured operational events omit prompts, recipients, names, coordinates and payloads. Public workflow output contains aggregate status only. Secret comparison runs before commits.                                                                             | Review vendor logs and future exception paths; full external log retention/redaction evidence remains open.                                                                      |
| Supply-chain compromise            | Locked dependency graph, CI clean install, vulnerability audit, CodeQL and release SBOM artifact. Installed licenses are recorded in the dependency document.                                                                                                      | Action references are version tags, not immutable SHAs. Full transitive license inventory and an independently verified secret-scanning gate remain release work.                |
| Backup exposure                    | Separate private backup bucket/credentials, seven-day expiry, independent deletion ledger, checksum verification and isolated restore filtering. Clean restores verify objects, readable streams and deleted-owner exclusion.                                      | Anyone with backup credentials can read retained data. Periodic restore and credential-access review remain operational duties.                                                  |
| Abusive compute/AI spending        | Atomic per-owner usage limits, bounded imports/queries, consent-aware AI quotas/deadlines, provider Gateway budgets, public-share limits and Free email allocations.                                                                                               | Pre-registration/auth and invalid-share traffic controls, global concurrency and workload percentile measurements remain open.                                                   |

## Highest-priority remaining checks

Complete auth-sensitive rate limiting, validate operational alert delivery, review remaining audit-event coverage and finish the broader parser/load/security journey matrix. Approved connector security is a separate gate that cannot be verified while all adapters are disabled. Use [incident response](incident-response.md) for suspected exposure or abuse and [authentication](authentication.md) for the exact session/deletion behavior.

Changes to ownership, public projection, import parsing, external AI context, credentials, backups or provider adapters require updating the relevant row and adding a regression that demonstrates the failure boundary.
